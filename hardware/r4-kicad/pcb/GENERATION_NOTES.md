# R4 KiCad board reconstruction — generation notes

`Reid_Orthotic_v2_LHS.kicad_pcb` / `Reid_Orthotic_v2_RHS.kicad_pcb` are
KiCad 7 boards (format `20221018`, generator `r4_gerber_reconstruction`)
generated by `../tools/generate_kicad_pcb.py` from:

* `../netlist/inventory_{lhs,rhs}.json` — verbatim gerber geometry
  (regenerated here with GM4 added, see below);
* the copper connectivity engine `../tools/copper_netlist.py`, re-run in
  process — the same union-find that produced
  `../netlist/copper_netlist_{lhs,rhs}.json` nets every pad, segment, arc,
  via and zone (the generator asserts its net ids/names/pad lists are
  identical to the committed JSON before emitting anything).

Companion `.kicad_pro` files carry the Default net class
(clearance 0.1 mm, track 0.15 mm, via 0.4/0.2 mm).

## Conventions chosen

* **Coordinates**: `kx = x_gerber − 240.0`, `ky = 300.0 − y_gerber`
  (Y flip; gerber is Y-up, KiCad Y-down). Rotations pass through
  unchanged — both conventions are visually CCW in top view.
* **Edge.Cuts source**: the inventory's previous `Edge.Cuts` (GM3) is the
  *fab drawing* (frame, scale bar, spec table) and contains **no** board
  outline. The physical outline lives on **GM4** ("Board Outline").
  `gerber_inventory.py` now maps GM4 → `Edge.Cuts` and GM3 →
  `Dwgs.User`; both inventories were regenerated (that is the only
  inventory change).
* **Board outline**: isolated by endpoint clustering (0.05 mm tolerance)
  and dropping open/small components (the green "Board Outline" caption).
  Result per side: **1 closed loop, 14 objects (8 lines + 6 arcs),
  bbox 21.25 × 46.25 mm**. No synthetic bridge was needed (the apparent
  0.73 mm right-edge gap is covered by a short as-drawn segment).
  Note: the "~40 × 74 mm" working estimate came from the caption-polluted
  copper bbox; the real board is 21.25 × 46.25 mm.
* **Footprints**: one per PnP component, anchored at the engine's
  transformed position (`gerber = pnp + (298.0, 245.5)`), rotation =
  `rot` (LHS, top) / `rot + 180°` (RHS, bottom, B.Cu). Pad centres are
  the matched gerber flash centres (not the idealised model), so they are
  exact by construction. Reference/value texts are hidden (originals have
  minimal silk). Values come from the PnP `Comment` column. The nRF52832
  exposed pad keeps the engine's pad number `"PAD"`.
* **Pad shapes** are decoded from the aperture definitions: circle,
  rect and obround apertures map 1:1; aperture-macro flashes are decoded
  from their primitives into rotated rects (1 poly), rotated ovals
  (2 circles + 1 poly) and roundrects (4 circles + 2 polys, corner radius
  from the circle radius). Pad `(at …)` angles are written as the shape's
  global angle (KiCad's convention), with footprint-local offsets from
  the inverse footprint transform. Shape-level check: reconstructed
  bbox vs gerber flash bbox agrees within < 0.01 mm for every flash.
* **Unowned copper pads**: each emitted as a single-pad footprint
  `R4:PAD_<net>_<n>` (refs `PAD1…`), `exclude_from_bom/pos`. 8 per side
  (TC2030 programming pads, fiducial-like discs, wire pads). The forty
  0.7 mm castellation/wire holes are thru-hole oval/round pads inside the
  J1–J4 footprints (ring size from the copper flash, drill 0.7 mm,
  `*.Cu *.Mask`, `remove_unused_layers`). The three 1.0 mm NPTH holes are
  `NPTH` footprints with `np_thru_hole` pads.
* **Tracks**: every copper line/arc → `segment`/`arc`, width = aperture
  diameter, net from the engine. **Vias**: plated holes ≤ 0.45 mm
  (0.2 mm drill/0.4 ring ×287|296, 0.3/0.6 ×9|13), per-via ring size from
  the matching flash, `F.Cu`–`B.Cu`, `remove_unused_layers`.
* **Zones**: one zone per dark pour region, outline = region polygon,
  net from the engine's pour label. As-built fills are stored:
  `filled_polygon` = pour minus the later clear (void) polygons in gerber
  draw order (shapely difference), fractured hole-free with 0.5 µm slit
  cuts. **Do not refill** unless you accept KiCad recomputing the pours
  (thermal/clearance settings are nominal: clearance 0.2, min width 0.1,
  thermal gap 0.2 / bridge 0.3).

## Mask / paste margins (derived empirically)

Comparing every pad flash with its mask/paste flash in the pad's own
rotated frame:

* **Solder mask: +0.05 mm per side** (global `pad_to_mask_clearance 0.05`).
* **Paste: 0 mm** (global `pad_to_paste_clearance 0`).
* Per-pad override: the U2 EP on both sides (`solder_paste_margin -1.7`; its as-built paste
  windows are additionally emitted as filled polys on F/B.Paste — 10 per
  side). Everything else matches the global values within 1 µm.
* Pads with no paste flash (castellations, test/wire pads) omit the
  Paste layer; all pads have mask openings (vias are tented).

## Dropped / retained oddities

* The copper gerbers carry plot captions ("Top Layer", "Bottom Layer")
  drawn as copper strokes *outside* the board outline. Per the generation
  contract every copper line was kept: **75 F.Cu + 116 B.Cu segments per
  side sit outside the outline** (they carry `NET<id>` nets, incl. the
  ~20 pad-less caption nets in the netlist). Select-and-delete outside
  the outline if you want a clean DRC.
* Silkscreen captions outside the outline were dropped (133–174 strokes
  per layer), as were all mask/paste layer caption strokes (the real
  mask/paste content is flash-only) and the GM3 fab-drawing content
  (frame, table, scale bar — 128 caption strokes on GM4 too).
* Real silkscreen exists only on the component side (F for LHS, B for
  RHS): 196 lines + 8 arcs each.

## Open issues for human review

1. **KiCad DRC not run** — `kicad-cli` is not installed in this
   environment; validation was done by re-parsing the s-expressions.
   (kicad-cli 7.0 has no `pcb drc`; DRC needs the GUI or KiCad 8+.)
   Open both boards in KiCad 7 and run DRC; expect complaints only about
   the out-of-outline caption segments (delete them if unwanted).
2. **Zone refill** will replace the stored as-built fills with KiCad's
   own pour engine (nominal thermal/clearance settings); fine for
   editing, but plots will no longer be gerber-exact. No zone priorities
   were set (pours don't meaningfully overlap).
3. ~~RHS mux EP mask/paste reliefs differ from LHS~~ -- RETRACTED: this was
   a generator bug (the RHS exposed pads were built from the coincident
   0.6 mm via-in-pad ring flash, with inflated margins compensating). Fixed;
   RHS and LHS mux EPs are identical 2x1 mm roundrects, global margins.
4. The castellation pads are plain thru-hole pads; KiCad 7 has no
   first-class castellation flag (the fab note "castellated edges" must
   travel separately).
5. Net names are the engine's (43 anchored names, rest `NET<id>`);
   U2 EP pad is numbered `"PAD"` (not "49") to match the netlist JSONs.
